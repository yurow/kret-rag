# RAG 查询测试页面使用指南

## 📋 概述

RAG Scheduler 服务提供了一个可视化的查询测试页面，用于测试和调试 RAG 系统的各个组件。

## 🚀 快速开始

### 1. 启动服务

```bash
# Windows
start-scheduler.bat

# Linux/Mac
./start-scheduler.sh
```

或者手动启动：
```bash
cd rag-scheduler
python app/main.py
```

### 2. 访问测试页面

打开浏览器访问：
- **上传测试页面**: http://localhost:8000/
- **查询测试页面**: http://localhost:8000/test-query
- **API 文档**: http://localhost:8000/docs

## 🔍 测试页面功能

### 核心功能模块

#### 1. 完整查询测试（推荐）
- **端点**: `POST /query/`
- **功能**: 执行完整的 RAG 流程
  - 向量检索相关文档
  - 构建带引用标记的上下文
  - 可选：调用 LLM 生成回答
- **返回内容**:
  - 检索结果列表（含相似度分数）
  - 构建的上下文字符串
  - 查询重写信息（如果启用）
  - 查询耗时

#### 2. 纯向量搜索测试
- **端点**: `POST /query/search`
- **功能**: 仅执行向量相似度检索
- **适用场景**:
  - 测试检索效果
  - 调试向量库
  - 验证 Embedding 质量
- **返回内容**: 原始搜索结果列表

#### 3. RAG 生成回答测试
- **端点**: `POST /query/generate`
- **功能**: 完整 RAG 问答流程
  - 检索相关文档
  - 调用 LLM 生成自然语言回答
  - 提供引用来源
- **依赖**: 需要 llm-session 服务运行在配置的地址
- **返回内容**:
  - AI 生成的回答
  - 引用来源列表
  - 查询耗时

### 配置参数

| 参数 | 说明 | 默认值 | 范围 |
|------|------|--------|------|
| top_k | 返回结果数量 | 5 | 1-20 |
| score_threshold | 相似度阈值 | 0.7 | 0.0-1.0 |
| use_hybrid | 混合检索（BM25 + 向量） | ✅ 启用 | - |
| use_rerank | Rerank 重排序 | ✅ 启用 | - |
| use_query_rewrite | 查询重写 | ✅ 启用 | - |

### 功能开关说明

#### 混合检索 (use_hybrid)
- **启用**: 结合 BM25 关键词检索和向量语义检索
- **优势**: 提高召回率，兼顾精确匹配和语义理解
- **禁用**: 仅使用向量检索

#### Rerank 重排序 (use_rerank)
- **启用**: 对初步检索结果进行二次排序
- **优势**: 提升 Top-K 结果的相关性
- **禁用**: 直接使用初始检索结果

#### 查询重写 (use_query_rewrite)
- **启用**: 对用户查询进行优化
  - 停用词过滤
  - 关键词提取
  - 同义词扩展
- **优势**: 提升长句和复杂问题的检索准确率
- **禁用**: 直接使用原始查询

## 💡 使用技巧

### 1. 测试查询重写效果
1. 输入复杂问题："什么是机器学习的优势和劣势？"
2. 启用 "查询重写" 选项
3. 点击 "完整查询"
4. 观察 "查询重写" 区域显示的原始查询和重写后查询对比

### 2. 对比不同检索策略
1. 输入相同问题
2. 分别测试以下组合：
   - 仅向量检索（禁用混合检索）
   - 混合检索（启用 BM25 + 向量）
   - 混合检索 + Rerank
3. 比较结果数量和相似度分数

### 3. 调试向量库
1. 使用 "仅向量搜索" 功能
2. 调整 score_threshold 观察结果变化
3. 检查返回的文档片段是否相关
4. 如果不相关，可能需要：
   - 重新训练 Embedding 模型
   - 调整分块策略
   - 增加训练数据

### 4. 测试 LLM 集成
1. 确保 llm-session 服务已启动
2. 使用 "RAG 生成回答" 功能
3. 检查：
   - AI 回答是否基于参考信息
   - 引用来源是否正确标注
   - 回答是否专业准确

## 📊 界面说明

### 统计信息面板
- **结果数量**: 返回的文档片段总数
- **查询耗时**: 从请求到响应的总时间（毫秒）
- **平均相似度**: 所有结果的平均相似度分数

### 结果展示
- **引用标记**: [引用 1]、[引用 2]...
- **相似度分数**: 以百分比显示（如 85.3%）
- **元数据**: 文档ID、分块ID、文件名等
- **内容预览**: 截取的文本片段

### JSON 响应查看器
- 显示完整的 API 响应
- 格式化 JSON，便于调试
- 可查看原始数据结构

## 🐛 常见问题

### Q1: 查询返回空结果
**可能原因**:
- 向量库中没有相关文档
- score_threshold 设置过高
- 查询问题与文档内容不匹配

**解决方案**:
1. 降低 score_threshold（如 0.5）
2. 检查是否已上传相关文档
3. 尝试不同的查询表述

### Q2: LLM 回答失败
**可能原因**:
- llm-session 服务未启动
- 网络连接问题
- API 配置错误

**解决方案**:
1. 确认 llm-session 服务运行在配置的端口
2. 检查 .env 文件中的 LLM_SESSION_URL
3. 查看服务日志排查错误

### Q3: 查询重写效果不明显
**可能原因**:
- 查询本身已经很简洁
- jieba 分词词典不包含专业术语
- 停用词列表需要调整

**解决方案**:
1. 尝试更复杂的长句查询
2. 自定义停用词列表
3. 添加领域专业术语到词典
